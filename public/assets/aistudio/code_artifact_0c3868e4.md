# מסמך אפיון וארכיטקטורה: כלי לאבחון איטיות במחשב מבוסס AI

## 1. מטרת המערכת
פיתוח כלי דיאגנוסטיקה חכם הפועל על המחשב המקומי של המשתמש. הכלי דוגם את משאבי המערכת (חומרה ותוכנה), שולח תמונת מצב בסיסית למודל שפה חכם (LLM), ומאפשר ל-AI לפעול כ"סוכן" (Agent) המפעיל כלי חקירה מתקדמים כדי לאתר את שורש הבעיה לאיטיות המחשב ולהציע פתרונות מעשיים.

## 2. ארכיטקטורת המערכת
המערכת בנויה משני רכיבים עיקריים:
1. **הלקוח המקומי (Local Client):** תוכנה שרצה על מחשב המשתמש, אחראית על דגימת הנתונים, ביצוע פקודות מערכת, ותקשורת מול ה-API.
2. **מנוע ההחלטות (AI Agent):** מודל מבוסס ענן המקבל את הנתונים, מחליט אילו כלים להפעיל, מנתח את התוצאות ומחזיר מסקנות.

## 3. טכנולוגיות וספריות מומלצות
אנו נתמקד בפיתוח באמצעות **Python**, בשל פשטות הגישה שלה למשאבי מערכת ושילוב נוח עם מודלי AI.

*   **שפת פיתוח:** Python 3.10+
*   **ספריות ליבה (Local Client):**
    *   `psutil`: קריאת נתוני מעבד, זיכרון, דיסק ותהליכים רצים (הספרייה החשובה ביותר בפרויקט).
    *   `wmi`: (Windows Management Instrumentation) לשליפת נתונים עמוקים יותר על חומרה, שגיאות ותוכנות אתחול.
    *   `winreg`: גישה לרישום של Windows (Registry) לקריאת תוכנות Startup.
*   **ספריות AI ותקשורת:**
    *   `openai` או ספריית ה-SDK הרלוונטית למודל שבו נבחר.
    *   `pydantic`: להגדרת מבני נתונים חזקים ואימות ה-JSON שחוזר מה-AI.
    *   `requests`: לתקשורת כללית במידת הצורך.

## 4. זרימת עבודה (Agent Workflow)
התהליך יתבצע במחזוריות (Loop) עד להגעה למסקנה:
1.  **Baseline Trigger:** הסקריפט אוסף נתונים בסיסיים (CPU %, RAM %, שטח דיסק) ושולח ל-AI.
2.  **Triage (הערכה ראשונית):** ה-AI מנתח את מצב הבסיס ומחליט איזה כלי חקירה חסר לו.
3.  **Tool Execution:** ה-AI מחזיר בקשה להפעלת כלי (למשל `get_top_memory_processes`). הסקריפט מריץ את הפונקציה המקומית.
4.  **Feedback Loop:** הסקריפט מחזיר ל-AI את תוצאות הכלי בפורמט JSON. ה-AI בוחן האם המידע מספיק. אם לא, הוא קורא לכלי נוסף.
5.  **Synthesis & Recommendation:** ה-AI מגבש דוח סופי בשפה פשוטה, מצביע על צוואר הבקבוק ומציע פעולה.

## 5. הגדרת הכלים (Tools Definition)
רשימת הפונקציות המקומיות שה-AI יורשה "לקרוא" להן:
*   `get_top_cpu_processes(limit: int)`: מחזיר את התהליכים העמוסים ביותר חישובית.
*   `get_top_memory_processes(limit: int)`: מחזיר את צרכני הזיכרון הכבדים ביותר.
*   `get_disk_io_status()`: מחזיר נתוני קריאה/כתיבה וצווארי בקבוק בדיסק.
*   `get_startup_apps()`: שולף תוכנות שנטענות עם עליית המחשב.
*   `get_background_services()`: רשימת שירותים פעילים שאינם שייכים לליבת המערכת.

## 6. תוכנית עבודה ושלבי פיתוח (Roadmap)

### שלב א': פיתוח שכבת האיסוף המקומית
*   הקמת סביבת Python.
*   כתיבת פונקציות `psutil` לאיסוף Baseline (ממוצע מעבד וזיכרון).
*   כתיבת הפונקציות המפורטות (Tools) ובדיקה שהן מחזירות JSON תקין ומדויק.

### שלב ב': הגדרת סביבת ה-AI (Agent)
*   הגדרת חשבון API (למשל OpenAI / Gemini).
*   כתיבת ה-System Prompt שמגדיר ל-AI את תפקידו (טכנאי מחשבים מומחה).
*   רישום הפונקציות שיצרנו בשלב א' כ-Tools בממשק ה-API.

### שלב ג': בניית לולאת התקשורת (The Loop)
*   כתיבת הקוד שמנהל את השיחה בין הסקריפט ל-AI.
*   טיפול במקרים שבהם ה-AI מבקש להפעיל פונקציה: קריאת הבקשה, הפעלת הפונקציה ב-Python, והחזרת התשובה ל-AI.

### שלב ד': ממשק משתמש וגימור (אופציונלי)
*   הוספת ממשק שורת פקודה (CLI) ברור ונעים לעין (שימוש בספריית `rich` למשל).
*   לחלופין, עטיפת הקוד בממשק גרפי פשוט באמצעות `Tkinter` או `PyQt`.
